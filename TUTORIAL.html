Drillr · drillr-social

Making TikTok carousels

A small command-line tool that turns five lines of copy into a seven-slide photo carousel. It is all in the zip — everything below runs on your own machine, and none of it costs anything.

What it actually does

Four steps, and the second one is a person.

  • plancopy gets drafted
  • approveyou read it
  • renderslides get drawn
  • publishupload

A post moves draft → approved → rendered → posted and cannot skip a step. That is deliberate: render only looks at approved posts, so nothing can be drawn, let alone posted, until a human has read the words. It is the whole reason this is four commands instead of one.

The part worth knowing up front

plan is the only command that talks to an API, and the only one that costs money. You can skip it entirely. node slideshow.mjs go hands you the exact same request on your clipboard, you paste it into any chatbot you already have, and it reads the answer back off the clipboard. Same copy rules, same review gate, no account needed.

Before you start

Three things, and only one of them takes any real time.

Node 20 or newer
Drives everything. nodejs.org/en/download — take the LTS build. Check it with node --version.
Python 3
Draws the slides. python.org/downloads. On Windows, tick Add python.exe to PATH in the installer — it is off by default and nothing works without it.
About 30 photos
Your own wallpapers. This is the real work — see step 4.

No GitHub account, no git, no npm install. Everything else is in the zip.

Windows: the two things that stop everyone

Neither is a bug in the tool. Both look like one. If you are on Windows, read this before Setup and you will skip about half an hour.

  1. The zip unpacks into itself

    Windows' built-in extractor makes a folder called drillr-social and puts the real drillr-social inside it. You end up one level too high, and Node says the file does not exist:

    what you see
    Error: Cannot find module 'C:\Users\you\Desktop\drillr-social\slideshow.mjs'
    code: 'MODULE_NOT_FOUND'

    Run dir. If it lists another drillr-social instead of slideshow.mjs, go one level deeper:

    terminal
    dir
cd drillr-social
node slideshow.mjs          # now it prints the command list

  2. pip is not recognized

    what you see
    'pip' is not recognized as an internal or external command,
operable program or batch file.

    This almost never means Python is missing. It means it was installed without being added to PATH, which is the default. Find out which:

    terminal
    py --version

    If that prints a version, Python is on the machine and only PATH is wrong. If it also fails, there is no Python yet. Either way the fix is the next step.

  3. Download the right installer

    On python.org/downloads, ignore the big yellow Download Python install manager button. Take the plain standalone installer on the line underneath it, or open the release page and scroll to Files:

    the row you want
    Windows installer (64-bit)    Recommended    ~32 MB

  4. Tick the PATH box

    On a fresh install, the first screen has Add python.exe to PATH at the bottom. It is off by default. Tick it before clicking Install Now. That single checkbox is the whole problem.

    If the installer instead opens on Modify Setup, that version is already on the machine and you just need to switch the option on:

    click through
    Modify  ->  Next  ->  Advanced Options
        ->  tick "Add Python to environment variables"
        ->  Install

  5. Open a new terminal and check

    An already-open window keeps the old PATH forever. Close it, open a fresh one, then:

    terminal
    python --version
pip install Pillow

    python --version has to print a version here. If it opens the Microsoft Store instead, Windows' stub is shadowing the real thing: Settings -> Apps -> Advanced app settings -> App execution aliases, and switch off both python.exe and python3.exe.

Why PATH specifically, and not just pip

Installing Pillow with py -m pip install Pillow works and is tempting, but it only gets you past this one message. The tool runs the literal command python when it draws slides and when it self-checks, so with PATH still broken, doctor reports Pillow missing even though you just installed it, and render fails outright. Fix PATH once and both go away.

If you ended up installing a second version alongside an older one, run pip install Pillow again after the PATH fix. Pillow went into the old Python; python now points at the new one. Having both installed is harmless.

Setup

Do these in order. Ten minutes, plus however long you spend picking photos.

  1. Unzip it

    Extract drillr-social.zip anywhere you like. Open a terminal in the folder it makes — every command below is run from there.

    terminal
    cd path/to/drillr-social
node slideshow.mjs          # prints the command list

    If that prints a list of commands, you are set. There is nothing to install — the tool runs on Node's built-in modules alone, and the one package listed in package.json is for plan, which you are not using.

  2. Install Pillow

    terminal
    pip install Pillow

    This is the image library that renders the slides. Nothing else to install.

  3. Fetch the fonts

    terminal
    node slideshow.mjs fonts

    Pulls four candidate fonts from Google Fonts. They are not in the repo because there is no reason to carry font binaries around when one command gets them. The tool is set to Fredoka already, so you can move on.

  4. Fill the photo pool

    Drop images into two folders. Nothing downloads them — you choose them, the tool rotates through them and remembers what it used.

    where they go
    backgrounds/players/    ← 20+ — the hook slide and all five numbered slides
backgrounds/stadiums/   ← 6+  — the app-mention slide only

    jpg, png or webp. Portrait is ideal; a landscape shot gets centre-cropped to 9:16, so skip anything with the subject far off to one side. Aim for calm, wide shots in stadiums/ — text has to sit on top of them.

    You need real numbers here: the renderer refuses to repeat a background inside one carousel, so a pool of six cannot fill a seven-slide post.

  5. Check it over

    terminal
    node slideshow.mjs doctor

    Prints every dependency, both photo counts, and what is in the queue. A line reading -- ANTHROPIC_API_KEY unset is fine and expected — that is the free path working as intended, not a problem to fix.

Making a carousel

The loop you will actually run.

Start here: one command does all of it

terminal
node slideshow.mjs go

It puts the brief on your clipboard, waits while you paste it into a chatbot, reads the reply straight back off your clipboard, shows you each carousel, and renders the ones you approve. No files to create, nothing to copy out of the terminal window.

It still stops and asks before anything renders. You type y to approve a carousel or press Enter to leave it as a draft. Everything below is the same loop done a step at a time, which is worth reading once so you know what go is doing on your behalf.

  1. Get the brief

    terminal
    node slideshow.mjs brief --count 10

    Prints what Drillr is, the copy rules, real past posts as examples, and a compressed read of everything the account has already said - a subject drawn from the angle pool for each carousel, the words the back catalogue has worn out, and the hooks used so far with a count each. It also puts the whole thing on your clipboard, so there is nothing to select out of the terminal.

  2. Paste it into a chatbot

    Claude, ChatGPT, Gemini, whatever you already use - the brief carries all its own context, so nothing depends on which one. Free tiers are fine. It comes back with a JSON array. Copy the whole reply.

    Do not bother tidying it. If it wraps the JSON in a sentence or a code fence, the importer finds the array anyway.

    Weaker models drift on the copy rules more, and the one rule that matters most - sell the outcome, never list what the app contains - is the one no automated check can catch. That is what the next two steps are for.

  3. Import and read it

    terminal
    node slideshow.mjs import

    With no arguments it reads your clipboard, which is where the reply already is. Prints each carousel as it queues it, and flags anything off - hype words, invented statistics, a colon in an item, a line long enough to render smaller than the rest of the set, five items all the same length. Fix wording directly in state/queue.json; the text fields are all free text.

    You no longer need drafts.json

    It used to be required, it is not any more, and it was the first thing every new machine tripped over: nothing ships one, so --from drafts.json on a fresh copy failed with ENOENT and looked like a broken tool. The clipboard is now the default.

    The file still works if you prefer one. Save the JSON array next to slideshow.mjs and run node slideshow.mjs import --from drafts.json. On Windows, check your editor did not quietly save it as drafts.json.txt.

  4. Approve

    terminal
    node slideshow.mjs list          # see the queue
node slideshow.mjs approve all

    This is the gate. Nothing renders until you do this, and doing it means you read the copy.

  5. Render

    terminal
    node slideshow.mjs render

    Writes out/<id>/01.jpg through 07.jpg at 1080×1920, plus a caption.txt with the hashtags already attached. That folder is the finished post.

  6. Post it, then close the loop

    terminal
    node slideshow.mjs publish <id> --manual

    Upload the folder to TikTok by hand, then run this. It does not talk to TikTok — it marks the post done so its hook joins the do-not-repeat list next time you run brief.

What does not work yet

So you do not go hunting for a bug that is not there.

Automatic posting is off

publish without --manual is a dry run. It prints what it would have sent and stops. This is deliberate and the blockers are TikTok's: photo carousels can only be pulled from a domain verified in TikTok's developer portal, and until an app passes their audit every post lands visible only to the poster. Uploading by hand is the current answer.

The slide order looks wrong but is not

Slides run hook → 1 → 2 → 3 → 4 → app mention → 5. The app mention is slide six, not seven, so the plug lands mid-swipe and the carousel ends on content rather than an advert. Leave it.

If something breaks

The three things that actually go wrong.

import says no such file, or the clipboard is empty

Easiest fix: drop the --from and run node slideshow.mjs import on its own. With no arguments it reads your clipboard, so there is no file to get wrong.

If you do want the file, you create it yourself - nothing ships one and no command writes it. It belongs beside slideshow.mjs, in the folder you run the commands from. The path in the error message is exactly where it was expected, so compare it against where you saved it. On Windows, check the name is not drafts.json.txt.

"clipboard is empty" or "the clipboard still holds the brief" means the copy did not take. Go back to the chatbot, select its whole reply, copy, and run the command again.

render says a background pool is too small

You have fewer photos than slides. Add more to backgrounds/players/. Run doctor to see the counts and how many have never been used.

render.py failed

Almost always Pillow missing. Check with python -c "import PIL" — silence means it is fine, an error means run pip install Pillow again and read what it says.

On Windows there is a second cause: typing python opens the Microsoft Store instead of running anything. That means Python is not properly on your path — reinstall from python.org with Add python.exe to PATH ticked.

nothing approved / nothing rendered

Not an error. It is the state machine telling you the previous step has not been done. Run list to see where each post has got to.

import skipped one of my carousels

It had no hook. That is the only thing that gets dropped, and it prints which one and why.

A repeated hook is not skipped. It queues, with a note that the hook has been used before, because reusing a strong hook with a different set of items is normal here. To go back to dropping duplicates, set copy.repeatHooks to false in config.json.
